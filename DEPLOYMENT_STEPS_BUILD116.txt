RebataTrack Website Build 116 - Deployment Steps

PURPOSE
- Make the private staff-facing experience consistently Admin Portal / Administration.
- Keep tester/customer-facing access consistently Beta Portal.
- Preserve all Website Build 115 functionality and infrastructure identifiers.

DEPLOYMENT ORDER
1. Deploy RebataTrack Beta Email Worker Build 116 first.
   Cloudflare > Workers & Pages > rebatify-beta-email > Edit Code.
   Replace the current Worker source with worker.js from the Build 116 package.
   Keep all existing Variables, Secrets, bindings, routes, and sender configuration unchanged.
   Save and Deploy.

2. Deploy Website Build 116 to the existing GitHub Pages repository.
   Use the smaller RebataTrack Website Build 116 GitHub Update.zip and replace the matching files.
   Or use the complete RebataTrack Website Build 116 package as the full baseline.

3. Wait for GitHub Pages to publish, then hard refresh the Admin Portal.

4. Verify private staff-facing terminology:
   - Admin sign-in says Administration / Private Admin Portal.
   - Admin sidebar brand says Administration in both Beta Program and Production workspaces.
   - No private staff-facing UI or admin notification email uses anything other than Admin Portal / Administration for the overall staff portal.

5. Verify tester/customer terminology remains unchanged:
   - Beta application and Beta Program content remain beta-specific.
   - Tester sign-in, tester settings, tester help, and tester communications say Beta Portal.

6. Verify existing functionality remains intact: administrator sign-in, Beta Program administration, applications, tester access, tasks, Help & Feedback, Production Admin, Support, Privacy, Terms, Delete Account, and Reset Password.

NO INFRASTRUCTURE MIGRATION IN THIS BUILD
- Do not rename Firebase project IDs, Firestore paths, deployed Worker names, GitHub Pages URLs, Android package IDs, iOS bundle IDs, subscription product IDs, sender addresses, or technical routes in this build.
